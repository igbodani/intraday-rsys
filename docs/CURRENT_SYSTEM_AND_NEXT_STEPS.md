## What the system is meant to do now

This is an **offline synthetic research-engine prototype**. It can replay declared synthetic data, construct causal bar histories, exercise account invariants, and run a small ORB or VWAP example through scanner ranking, proposals, cash reservation, modeled execution, position protection, metrics and retained reports. It is useful for testing software behavior before buying data or conducting market research.

There are two public execution paths with deliberately different input schemas:

- `rsys replay` uses `ReplayConfig`, the R3 event/data pipeline, coverage declarations, bar builders, revisions and optional synthetic observers. Its `execution.data_basis` remains `inactive`: it does not produce trade P&L.
- `rsys run` accepts legacy version-1 `synthetic_standalone` bars and version-2 `synthetic_sessions` bar/trade configurations. A version-2 file runs several sessions with shared account/risk state, fresh daily strategies and retained inputs, fills, partial failures, metrics and reports. Strategies receive bounded replay contexts. Bar opens and subsequent-trade fills are explicit synthetic execution estimates; no provider credentials or real data partitions are supported.

`BarSessionRunner` is the canonical bar-input engine; `rsys.standalone_run.StandaloneRunner` remains a compatibility alias; its source clock and decision views use ReplayRunner. `TradeInputRunner` is the public version-2 trade mode's engine for synthetic trade-built bars and subsequent-trade execution. It now schedules decisions at phase 40, exits at 60 and rank-ordered entries at 70. Neither API is an audited real-data loader.

A successful finite synthetic input is not evidence of a complete historical trading day. Version-2 composition requires every intermediate session to end flat. A final open snapshot needs the explicit diagnostic completion policy. If flatten or max-hold is configured, an outstanding required exit without an eligible subsequent reference makes the attempt fail as incomplete. No overnight trading policy has been authorized.

## Is the existing work good and testable?

The modular boundaries are useful: Decimal account arithmetic, proposal records, strategies, scanner ranking, bounded views and evidence persistence can be exercised independently. The public CLIs now provide repeatable integration checks. The repair added failure-producing regression cases before changing the unsafe behavior, then tested the actual session runner and retained artifacts.

The original 557 green tests were insufficient evidence for execution correctness. In particular, the account fixture interpreter and the session runner implemented different execution timing, and several tests encoded the mistaken “no entry-bar exit” or “fill at publication using a past open” behavior. A fixture oracle also ignored several expected fields. Those are material defects, not cosmetic test gaps. The repair addresses them and adds whole-run future-prefix and negative-control tests.

The architecture follows the declared path for synthetic bar and trade slices. It remains partial M2 overall. Shared transitions reduce duplication, while each execution model retains explicit policy. [test_develop_regressions.py](../tests/test_develop_regressions.py) adds real-run checks for session accounting, phase order, bad quality, timer causality, future history and statistics. Passing helpers do not establish provider coverage or a complete public research workflow.

## Corrected behavior that callers must account for

The scanner-history review repairs reject invalid volume/price/status/revision inputs, naive timestamps and nonpositive/non-integer elapsed minutes. Calendar-ineligible short sessions retain a `SESSION_TOO_SHORT` explanation without inspecting their observations. Equal revisions with conflicting source/availability metadata are rejected in either input order; exact duplicates contribute once. [test_minute_history_repairs.py](../tests/test_minute_history_repairs.py) adds 27 cases, including a full ranking/evidence future-invariance check with an eligible-past-change negative control. Two additional [public-session tests](../tests/test_public_sessions.py) emulate Windows newline translation in both input modes: traces are written and hashed as the same UTF-8/LF bytes, comparison succeeds, and altered file bytes still fail integrity checks. The new regressions produced 27 failures before the fixes; all 814 tests and Ruff pass after them on Linux. The Windows check is an emulation, not a native Windows run.

1. An entry at the 09:46 open is recorded at 09:46. It no longer waits until the 09:47 close to pretend the earlier open was available. A decision arriving at 09:46:30 must wait for a later eligible open.
2. Entry-interval stops and targets are active. The interval's low/high become usable for conservative settlement at publication. Stop takes priority when OHLC cannot order both touches. No exact touch time is invented.
3. Timers exist independently of market observations. A 09:48 flatten cannot use the 09:47 open. Missing subsequent execution data produces an incomplete attempt.
4. Reservations belong to intents. Callers should retain `AcceptedIntent.reservation_id` and supply it to cancellation/fill operations. Amount-only compatibility is limited to an unambiguous reservation; it cannot clamp or release someone else's cash.
5. Fill-time sizing uses actual modeled entry price, current free cash plus the intent's own reservation, the configured risk budget (recomputed from current equity in version 2) and a cap at accepted quantity. Gap prices can reduce size or reject; they cannot borrow cash.
6. Completed-trade statistics use net P&L including entry and exit fees. Open positions use the last published mark. Account equity and trade statistics answer different questions and are both retained.
7. Version-2/3 run manifests identify execution/scanner/account bases, resolved strategy and execution settings, source/dependency/config/data hashes and chronological trace hashes. Version 3 also seals complete input, resolved settings, session files, fills, metrics and reports. Old version-1 manifests must be rerun before comparison. They are not silently upgraded or treated as equivalent evidence.
8. Each session rejects unknown settings, mismatched declared dates, offset/sub-millisecond timestamps, out-of-session data, invalid OHLC/volume, premature completed bars and unsupported evidence labels. Version 2 accepts an ordered list of separately validated sessions. `strategy_config` is forwarded and retained rather than ignored.
9. Session transaction IDs are dated. Duplicate/reversed dates are rejected; a partially failed coordinator cannot silently retry or advance. Open positions still block overnight composition.
10. Trade timers require a market print after the exit request, even when earlier prints arrive late. Quality flags are preserved and invalid input fails closed. Sizes/conditions/tape are preserved, and same-batch corrections invalidate execution references before fills.
11. Scanner history excludes current/future sessions at both provider and composition boundaries. The minute-addressable provider (module 21) is now connected through `MinuteHistoryScanner` (module 22) at each public replay decision. Freshness limits and coverage gaps exclude candidates; exact chosen historical revisions and bounded current versions are retained.
12. Multi-session statistics use actual midnight-relative fill timestamps, scheduled-session clipping and starting equity. Drawdown remains session-end-only; an open exposure interval extended to scheduled close does not assert a fill or data completeness.
