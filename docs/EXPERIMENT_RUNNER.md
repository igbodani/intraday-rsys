# Finite experiments on saved data

`rsys experiment --plan PLAN_JSON --out ROOT` runs a baseline and a fixed list of
named variations through the existing historical backtest. It requires pinned local
objects, never downloads data, and never chooses a winner or opens the final holdout.
It supports the existing ORB/VWAP completed-bar strategies and supported 2024 calendar.

## Prepare and run

1. Start from a working historical backtest config with explicit data pins, dates,
   partition permissions, action attestation, scanner, account, risk and cost settings.
   The config generated by [provider validation](ALPACA_PROVIDER_VALIDATION.md) is a
   suitable starting point after its data/manual checks. Synthetic cached fixtures
   can test the software without credentials; they do not establish market performance.
2. Copy [the experiment example](../configs/experiment.example.json). Set the base
   config path, study ID, hypothesis, comparison category/axis, exact variants,
   trial limit and failure policy. Paths resolve relative to their owning files.
3. List any external/manual attempt references in `external_attempts`. Each declared
   reference consumes one budget slot. This is a declaration, not an audit of outside
   activity. Keep the original references and hypothesis with the study.
4. Run the command and inspect the printed JSON/HTML report and manifest paths:

```bash
uv run rsys experiment --plan /local/study.json --out /local/research
uv run rsys status --storage-root /local/research --id PARENT_INVOCATION_ID --json
```

The example's two-trial budget is illustrative, not an approved research budget.
The base example remains blocked until real inputs/settings are explicitly supplied.
No credentials are read or required by experiment execution.

## Plan version 1

All fields are required: `schema_version: 1`, `study_id`, `hypothesis`, `study_kind`,
`base_config`, `variants`, `permitted_axis`, `trial_limit`,
`counting: "all_execution_attempts"`, `failure_policy: "stop" | "continue"`, and
`external_attempts` (an explicit list, possibly empty).

Each variant has a unique `name` and nonempty `changes`. Each change is an array of
known keys in `path` plus a literal JSON `value`. There are no expressions, arbitrary
Python, wildcard patches or automatic parameter combinations. `baseline` is reserved.
Every variant is validated before any cache read or child execution, so an invalid
last variant cannot leave a valid first variant running.

| Study category | Allowed examples | Comparison axis |
|---|---|---|
| `scanner` | `scanner.top_n`, lookback length, liquidity/freshness settings | `scanner_profile` |
| `entry` | ORB range/buffer/deadline; VWAP warmup/slope/pullback/confirmation | `strategies` |
| `exit` | `strategy.strategy_config.target_r` | `strategies` |
| `exit` | `account.flatten_at`, `account.execution.max_hold_ms` | `execution_mode` |
| `costs` | fees, adverse bps, feed delay | `cost_profile` |
| `account` | initial cash; risk/max quantity; quantity increment | `initial_cash`; `risk_profile`; `cost_profile`, respectively |
| `complete_system` | ORB versus VWAP, or combined strategy settings | `strategies` |

One plan permits one comparison axis. Different axes cannot be combined, including
an exit target change plus a holding-timer change. Tick size belongs to a complete
system study because it can affect both entry and exit. Unknown settings fail closed.
Dates, source objects, feed, mapping, partitions, action evidence and timing basis
cannot be patched. Changing a scanner search budget cannot silently add/remove pinned
objects. Existing comparison checks still reject a changed data identity.

## Budgets, retries and retained failures

Before each child is prepared, `studies.db` reserves a slot transactionally. Two
coordinators competing for the final slot cannot both receive it. Failed preparation,
failed execution and interruptions consume their reserved slot; operational checks
and the parent coordinator do not count as strategy trials.

The study's complete plan/base config, external references and limit are frozen in
that registry. Rerunning the same plan in the same root preserves the consumed count.
A rerun starts fresh simulations of the listed arms; it does not resume an interrupted
portfolio. Insufficient remaining budget produces `blocked_budget` rows. A changed
plan or budget under an existing study ID is rejected and retained as a failed parent.
A new code revision can rerun the same fixed plan within its remaining budget; each
coordinator freezes its code/dependency identity and compares only its own arms.

`stop` leaves later arms `not_started` after an execution failure. `continue` records
the failure and proceeds. Ctrl-C retains the interrupted arm and leaves later arms
unstarted. Hard termination may leave a reserved trial marked `running`; it stays
counted. Use its child invocation/run IDs with the existing status/recovery tools;
there is no automatic trial deletion or slot refund. Older trial rows remain visible
in every subsequent report's registry inventory.

The registry is local bookkeeping, not security-proof global trial accounting:
changing study IDs/storage roots, modifying the database or omitting outside attempts
can evade a global budget. These actions must be disclosed in real research.

## Evidence and interpretation

Parent artifacts live in `experiments/<invocation-id>/`: `experiment.json`, escaped
`report.html`, and a manifest with hashes/diagnostic seal. The original plan, base
identity, all expanded arm configs and checkpoints remain inspectable. Each child
uses the existing invocation, run database, `attempts/<run-id>` inputs, trace, fills,
metrics and reports. Frozen child config includes its study/plan/parent/trial linkage.
The source/dependency identity is checked at child creation and around execution.

The scorecard displays net account change after modeled costs, completed trades,
win rate (fraction), expectancy (currency per completed trade), profit factor (ratio),
exposure (fraction), and session-end drawdown in currency/fraction/percent. A stored
`max_drawdown_pct` of `0.25` means **25%**, not 0.25%. It is not worst intraday drawdown.
No trades/no losses retain explicit unavailable/undefined states rather than invented
infinite profit factors. Failed/tampered/incompatible arms remain listed as unavailable;
missing metrics are not replaced with zero. Successful execution and comparable
sealed evidence are separate statuses. A partial study returns nonzero.

ORB versus VWAP is a complete-system account comparison. Even an exit-only setting
change reruns the full account because holding time changes later affordability.
This is not common-entry causal attribution. MFE/MAE, common-entry windows, confidence
intervals, optimization, automatic winners and promotion gates are outside BR-06.
Results remain `unscored`; D16/D17 and final evaluation remain unchanged. Real-data
reconciliation and a prespecified chronological validation protocol are still needed.
The network guard is a Python socket/DNS tripwire for this serial workflow, not an OS
sandbox for arbitrary extensions/subprocesses.
